# Стыки

Перечерчивает однониточную схему станции с фото или скана на миллиметровку, расставляет изолирующие стыки и светофоры и составляет таблицы маршрутов по методичке ДВГУПС «Проектирование схематического плана станции» (`manual.pdf`).

## Установка

Скачать `StationJoints-Setup-X.Y.Z.exe` из [релизов](https://github.com/viirtualp1/station-joints/releases/latest) и запустить. Права администратора не нужны. О новых версиях программа сообщит сама.

## Как пользоваться

1. **Файл → Открыть** – фото или скан схемы из задания.
2. Программа распознаёт схему, расставляет стыки и светофоры, считает маршруты и проверяет схему по методичке.
3. При необходимости поправить:
   - **Стык** (J) – клик по пути ставит стык; выбранный: Del – удалить, N – габарит/негабарит, перетаскивание мышью – сдвинуть вдоль пути (шаг 5 мм);
   - **Пути** (T) – исправить распознавание: тянуть от узла или пути – новый отрезок, клик по отрезку и Del – удалить, клик по концу пути – тупик / перегон / п/п;
   - **светофоры** – клик по светофору (или правой кнопкой – меню): имя, тип, удалить, «как по правилам»; у выбранного стыка – «добавить светофор»;
   - **Объясни** (F1) – клик по объекту показывает, почему он здесь, со ссылкой на методичку.
   Ручные правки сохраняются в `.stj` и переносятся при смене листа или направления.
4. **Файл → Сохранить** – работа сохраняется в `.stj`, её можно открыть позже или переслать.
5. **Экспорт** – PDF для печати (М 1:1), PNG или ведомость для записки (Word): стрелки, участки, светофоры, стыки и таблицы маршрутов.

Слева – настройки листа (один или два листа, формат), направление движения и слои.
Справа – свойства выбранного, списки светофоров, изолированных участков и маршрутов.

### Маршруты

Вкладка **Маршруты** – таблицы из раздела 3 методички: основные и вариантные поездные
маршруты (приём с каждого входного на каждый путь, отправление с каждого пути на
правильный и неправильный путь перегона) и простые маневровые. У маршрута – положение
стрелок (`+` по прямому ходу, `−` по ответвлению, съезды парой: `+14/16`) и участки;
клик по маршруту подсвечивает его на схеме. Основной маршрут – с наименьшим числом
отклонений по стрелкам. Охранные стрелки (в скобках в табл. 3.1) программа пока не
определяет – их нужно дописать по табл. 2.1.

## Горячие клавиши

| | |
|---|---|
| Ctrl+O / Ctrl+S / Ctrl+Shift+S | открыть / сохранить / сохранить как |
| Ctrl+Z / Ctrl+Y | отменить / повторить |
| V / J / T | выбор / стык / пути |
| F1 | «Объясни» |
| Ctrl+R | расставить стыки заново |
| Ctrl+P / Ctrl+E | PDF / PNG |
| Del / N | удалить выбранное / габарит стыка |
| Колесо, 0, + / − | зум, вписать |
| Ctrl+Tab / Ctrl+W / F2 | следующий таб / закрыть / переименовать |

## Разработка

```
parser.py   – распознавание картинки в граф путей
joints.py   – анализ станции и расстановка стыков (п. 2.2–2.4)
layout.py   – компоновка на миллиметровке
signals.py  – светофоры (п. 2.5)          routes.py  – маршруты (раздел 3)
checks.py   – самопроверка по методичке   explain.py – режим «Объясни»
scene.py    – сцена для интерфейса        server.py  – бэкенд (JSON через stdin/stdout)
render.py, sheets.py, vedomost.py – PNG, PDF на листах, ведомость Word
app_flutter/ – интерфейс (Flutter, Windows)
```

Тесты:

```bash
pip install -r requirements-dev.txt
python -m pytest                 # бэкенд: правила методички на samples/, команды, файлы
cd app_flutter && flutter test   # интерфейс с настоящим бэкендом (нужен python в PATH)
```

`python cli.py samples/var96_pdf.png out.png --letters` – схема и текстовый отчёт без интерфейса.

## Сборка и выпуск

Локально: `python build.py` (нужны Python, Flutter SDK, Visual Studio Build Tools с C++
и Inno Setup 6) – установщик и архив появятся в `dist/`.

CI/CD – GitHub Actions (`.github/workflows/`):

- **CI** (`ci.yml`) – на каждый push и pull request: `pytest`, `flutter analyze`, `flutter test`.
- **Release** (`release.yml`) – собирает установщик на Windows и выкладывает выпуск.

Выпустить новую версию:

1. поднять `version:` в `app_flutter/pubspec.yaml` (например, `2.3.0+10`);
2. закоммитить в `main` и поставить тег с той же версией:
   ```bash
   git tag v2.3.0
   git push origin main v2.3.0
   ```
3. через ~15 минут в [Releases](https://github.com/viirtualp1/station-joints/releases) появятся
   `StationJoints-Setup-2.3.0.exe` и архив; установленные программы предложат обновиться сами.

Если тег не совпадает с версией в `pubspec.yaml`, выпуск остановится с понятной ошибкой.
Собрать установщик без выпуска – Actions → Release → Run workflow (файлы – в артефактах запуска);
в pull request, где меняется сборка (`build.py`, `installer.iss`, `pubspec.yaml`…), она запускается сама.
