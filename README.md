# Схема станции → изолирующие стыки

Программа загружает картинку однониточной схемы станции (фото или скан задания
из прил. 4 методички), распознаёт путевое развитие, перерисовывает схему в
векторном виде и расставляет изолирующие стыки по п. 2.4 пособия
«Проектирование схематического плана станции…» (ДВГУПС, 2017).

## Архитектура

- **Python – движок** (`parser.py`, `joints.py`, `layout.py`, `signals.py`, `checks.py`,
  `sheets.py`, `render.py`): распознавание, стыки, светофоры, проверка, PDF/PNG.
- **`server.py` – бэкенд для интерфейса**: команды и ответы – JSON по строке через
  stdin/stdout (`ping`, `load`, `relayout`, `scene`, `recompute`, `add_joint`,
  `remove_joint`, `toggle_negab`, `save_project`, `thumb`, `export_png`, `export_pdf`,
  `export_docx`).
- **`project.py`** – файл работы `.stj`; **`tables.py`** – таблицы участков, стрелок,
  светофоров, стыков; **`vedomost.py`** – ведомость в Word.
- **`scene.py`** – схема как JSON-сцена: векторные примитивы в мм (их записывает тот же
  `render.py`, так что размеры обозначений прил. 1 – в одном месте) и объекты для
  взаимодействия (стыки, пути, светофоры).
- **`app_flutter/` – интерфейс на Flutter** (Windows): рисует сцену векторно, сам
  запускает бэкенд. Бэкенд ищется так: `STATION_BACKEND` → `backend/server.exe` рядом
  с приложением → `server.py` выше по дереву (разработка, через `python`).
- `app.py` – прежний интерфейс на customtkinter (оставлен до перехода).

## Запуск (разработка)

```
pip install -r requirements.txt
cd app_flutter
flutter run -d windows                 # интерфейс; бэкенд – server.py через python
python ../cli.py схема.jpg out.png --grid --sheets листы.pdf   # без интерфейса
```

Визуальная проверка без экрана (интерфейс рисуется в памяти, снимки в PNG):

```
cd app_flutter
flutter test test/visual_test.dart --dart-define=SHOTS=C:\путь\к\папке
```

## Сборка и выпуск версий

```
python build.py            # Flutter + бэкенд -> dist/StationJoints/, установщик и zip
python build.py legacy     # прежняя версия на customtkinter -> dist/StationJoints.exe
```

Нужны Flutter SDK, Visual Studio Build Tools (компонент C++) и Inno Setup 6
(`winget install JRSoftware.InnoSetup`). Результат в `dist/`:

- `StationJoints-Setup-X.Y.Z.exe` (~44 МБ) – установщик: без прав администратора,
  ярлык в «Пуске», файлы `.stj` открываются двойным щелчком, удаление – через
  «Параметры → Приложения»;
- `StationJoints-win64.zip` (~62 МБ) – портативная версия: распаковать и запустить.

Python у пользователя не нужен. Плагинов с нативным кодом нет (диалоги – через FFI).

### Как выпустить новую версию

1. Поднять `version:` в `app_flutter/pubspec.yaml` (например, `1.0.0+1` → `1.1.0+2`) –
   это единственное место, где задаётся версия.
2. `python build.py`.
3. На GitHub в **публичном** репозитории `viirtualp1/station-joints-releases`
   (исходники остаются в приватном) → Releases → Draft a new release:
   тег `v1.1.0`, в описании – что нового, приложить `StationJoints-Setup-1.1.0.exe`
   (и при желании zip) → Publish release.
4. Всё: у установленных программ при запуске появится значок «Обновление 1.1.0»,
   кнопка «Обновить» скачает установщик, закроет программу, тихо обновит и
   запустит новую версию.

Репозиторий для обновлений – константа `updateRepo` в `app_flutter/lib/update.dart`.
Программа читает `https://api.github.com/repos/<updateRepo>/releases/latest` – без
токенов, поэтому репозиторий должен быть публичным. Сборки из разработки
(`flutter run`, тесты) обновления не проверяют.

Размер: основное – OpenCV (`cv2.pyd`, 82 МБ из 156). Из сборки вырезаны видео OpenCV,
форматы Pillow AVIF/WebP, Tk и OpenSSL; установщик сжат LZMA2.

## Защита работы

- Отмена / повтор: Ctrl+Z, Ctrl+Y (Ctrl+Shift+Z), кнопки в шапке; в подсказке – что
  именно отменится. История – до 100 шагов, включая перекомпоновку и «Расставить заново».
- Закрытие окна с несохранёнными правками – вопрос «Сохранить / Не сохранять / Отмена».
- Автосохранение: раз в 30 с, если есть правки, – резервная копия в
  `%APPDATA%\StationJoints\autosave\`. Открытый файл при этом не трогается. Если
  программа закрылась, не сохранив правки, при следующем запуске она предложит
  восстановить работу.

## Интерфейс (Flutter)

Инженерный стиль: схема на весь экран, тонкая панель инструментов, сворачиваемые
боковые панели, моноширинные ординаты, цвет – только для выделения.

- инструменты: **Выбор** (V) – клик по стыку/светофору/пути показывает свойства,
  перетаскивание двигает лист; **Стык** (J) – клик по пути ставит стык;
- выбранный стык: Del – удалить, N – габарит/негабарит, ПКМ – меню;
- колесо – зум к курсору, 0 – вписать, +/− – зум;
- слева: исходник, режим «Два листа» и формат, направление движения, слои;
- справа: «Свойства», «Светофоры» (клик – плавный переход к светофору), «Участки»
  (рельсовые цепи по горловинам: стрелки, число стыков, длина; клик – подсветка
  и переход, > 3 стрелок – красным);
- строка состояния: число замечаний самопроверки (подробности – в подсказке);
- «Файл»: Открыть (Ctrl+O), Сохранить работу (Ctrl+S), Сохранить как (Ctrl+Shift+S),
  недавние; на стартовом экране – карточки недавних с миниатюрами;
- «Экспорт»: PDF на два листа М 1:1 (Ctrl+P), PNG (Ctrl+E), ведомость для записки (Word);
- открыть файл из командной строки: `StationJoints.exe схема.jpg` или `работа.stj`.
- **табы**, как в VS Code: каждая открытая схема – в своём табе со своими зумом,
  выделением и историей отмены; Ctrl+Tab / Ctrl+Shift+Tab – переключение, Ctrl+W или
  средняя кнопка мыши – закрыть; у несохранённого таба – точка; «+» – открыть ещё.
  Уже открытый файл не дублируется – таб становится активным. Программа запускается в
  одном экземпляре: двойной щелчок по `.stj` открывает файл в уже открытом окне.

## Файл работы `.stj` (`project.py`)

Zip-архив: `project.json` (граф после распознавания, стыки с ручными правками,
настройки листа и направления), исходная картинка, надписи, миниатюра. Файл
самодостаточен – его можно переслать. При открытии распознавание не повторяется
(доли секунды), схема восстанавливается точь-в-точь. Недавние – в
`%APPDATA%\StationJoints\recent.json`, миниатюры – там же в `thumbs\`.
Смена формата листов или направления перекомпоновывает схему без повторного
распознавания, но ручные правки стыков при этом сбрасываются.

## Ведомость для записки (`vedomost.py`)

«Экспорт» → «Ведомость для записки (Word)»: документ .docx (A4, Times New Roman) с
таблицами – стрелочные переводы, изолированные участки, светофоры, изолирующие стыки
с правилом и обоснованием. Собирается без сторонних библиотек.

## Два листа (`sheets.py`, `layout.spread_to_sheets`)

Карточка «Лист»: переключатель «Два листа (горловины раздельно)» и формат A4/A3/A2
(по умолчанию выключено; формат по умолчанию A3). Так чертят вручную на миллиметровке: нечётная горловина
на листе 1, чётная – на листе 2, пути парка вытянуты через оба листа, в середине
остаётся место под остальное оформление.

## Направление движения

Карточка «Движение» → «Нечётная горловина: слева / справа». По умолчанию **справа**
(требование преподавателя): нечётные поезда идут справа налево, чётные – слева направо.
В пособии (рис. 2.17, прил. 3) наоборот – нечётная горловина слева; этот вариант – «Слева»
(в CLI – флаг `--odd-left`, в коде – `joints.ODD_RIGHT`). От выбора зависят входные
Н/НД и Ч/ЧД, чётность стрелок, тупиков и маневровых, буквы выходных; главные I и II
остаются снизу/сверху.

- после компоновки схема растягивается по оси станции – там, где её пересекают только
  горизонтальные пути парка (горловины не меняются, диагонали сохраняют наклон);
- длина вставки подбирается так, чтобы каждая горловина с запасом заполнила свой лист;
- линия склейки – посередине пустых путей, видна на экране красным штрихом; ось станции
  с номерами путей – в 30 мм от неё на листе 1;
- меню «⋯» → «Печать на 2 листа (PDF)» (Ctrl+P): два листа в натуральную величину
  (1 мм = 1 мм, 300 dpi), полоса перекрытия 10 мм, рамка 20/5 мм, подпись листа;
- без режима «Два листа» печать тоже работает: разрез подбирается у оси станции.

Пособие (п. 2.1) ограничивает только высоту чертежа (210, 297, 420… мм), длина не
лимитируется – разбивка по длине на листы этому не противоречит.

## Что делает

1. **Распознавание** (`parser.py`): бинаризация, исправление наклона фото,
   отделение надписей («п/п», номер варианта), скелетизация, построение графа
   (концы, изломы, стрелки), распознавание тупиковых упоров `]`.
2. **Анализ** (`joints.py`): главные пути I/II, пути станции (4, 6… / 3, 5…),
   съезды, стрелочные улицы, нумерация стрелок (нечётная горловина – 1, 3, 5…,
   чётная – 2, 4, 6…, стрелки съездов и улиц — подряд, п. 2.3).
3. **Стыки** — буквы как на рис. 2.7 пособия:
   - а — отделение станции от перегона;
   - б — выделение главных и приёмо-отправочных путей;
   - в — бесстрелочный участок за входным светофором (НП, НДП, ЧП, ЧДП);
   - г — отделение тупиков и подъездных путей;
   - д — короткая РЦ (25 м) на входе с подъездного пути;
   - е — каждая стрелка стрелочной улицы отдельно (негабаритные, в кружке);
   - ж — стык между стрелками съезда; между соседними стрелками с ответвлениями
     в разные стороны (параллельные передвижения). Если ответвление смотрит в
     промежуток между стрелками, стык негабаритный;
   - и — не более 3 стрелок в участке (добавляется, пока правило нарушено).
4. **Участки**: названия по п. 2.4 (`5-15СП`, `IП`, `НДП`, `9/19П`…), список – во вкладке «Участки».

## Проверка по методичке (`checks.py`)

В отчёте – раздел «Проверка по методичке» (✓/✗ по каждому пункту): нумерация путей,
тупиков (1Т, 3Т… / 2Т, 4Т…) и стрелок по горловинам (п. 2.2–2.3), непрерывная нумерация
съездов и улиц, правила стыков б, в, г, е, ж, и (п. 2.4), поездные светофоры у габаритных
стыков, входные Н/НД и Ч/ЧД на одном уровне, выходные с обоих концов путей, нумерация
маневровых (п. 2.5), отсутствие наложений светофоров и геометрия чертежа.

На чертеже также: ось станции (штриховая) с номерами путей и стрелками «в обе стороны»
(пути обезличены, п. 2.2), номера тупиков, номер стрелки – со стороны поля или широкого
междупутья (п. 2.3). Буквы правил у стыков – опционально (по умолчанию выключены,
в `cli.py` – флаг `--letters`), на расстановку и раздвижку схемы они не влияют.

## Светофоры (`signals.py`, п. 2.5 пособия)

- **Входные** Н, НД, Ч, ЧД — у стыка «а», мачтовые: Ж–З–К–Ж + лунно-белый пригласительный.
- **Выходные** — с каждого пути станции с обоих концов (пути обезличены), у стыка «б»:
  Н + № пути в чётной горловине, Ч + № в нечётной. С главных — мачтовые
  (Б–К–Ж–З–Ж от мачты, с трансформаторными ящиками), с остальных — карликовые в два ряда
  (К–Б / Ж–З–заглушка). Маневровые с путей совмещены с выходными (пункт а).
- **Маневровые** М1, М3… в нечётной горловине, М2, М4… в чётной, номера растут к оси станции:
  б) из тупиков и с подъездного пути — у стыка, ближайшего к стрелке (с п/п — мачтовый),
  запрещающий огонь красный; в) с участков за входными — у стыка «в»;
  г) для угловых заездов — перед первой стрелкой стрелочной улицы (если есть место).
- Светофор стоит справа по ходу движения, основание — в створе со стыком, огни — по ходу.
  Размеры по прил. 1: огонь Ø3 мм, стойка мачты 6 мм, ящик 4 мм; цвета огней —
  условными знаками (красный — чёрный круг, жёлтый — штриховка, лунно-белый — круг в круге,
  синий — точка в круге, зелёный — пустой круг, заглушка — крест).
- Стыки со светофорами ставятся не ближе длины светофора к стрелке, а если в ту же сторону
  уходит диагональ — дальше, чтобы огни её не пересекали; раздвижка схемы это учитывает.
- Чекбокс «Светофоры», список с ординатами — в отчёте.

## Миллиметровка (`layout.py`)

После распознавания схема перечерчивается «на миллиметровой бумаге»:

- междупутье = 1 клетка = 10 мм, каждый путь — на линии сетки 10 мм;
- все диагонали одного наклона: 10 мм по высоте на 15 мм по горизонтали
  (на два междупутья — 30 мм, на три — 45 мм; константа `DIAG_RUN` в `layout.py`);
  все узлы (стрелки, повороты, концы) — на линиях сетки через 5 мм (`GRID_X`),
  поэтому оба конца каждой диагонали лежат на линиях сетки; стыки — на целых мм;
- ординаты стрелок — в мм (список в отчёте), там же проверка «все диагонали
  нужного наклона, все узлы на сетке»;
- размеры обозначений по прил. 1: стрелка — тонкая линия 5 мм и закрашенный
  прямоугольник 3×1 мм со стороны остряков на стороне ответвления; стык — 2 мм,
  полочки 2 мм; негабаритный стык — окружность Ø 6 мм; номера стрелок — шрифт 3,5;
- нормы расстояний: стрелка–стрелка ≥ 14 мм, стык–стык ≥ 8 мм, стык у остряков
  7 мм (за обозначением стрелки), стык за ПС по габариту, участок НП/ЧП ≥ 30 мм,
  путь между стыками б ≥ 30 мм, зазор между несвязанными отрезками на одной
  линии ≥ 15 мм;
- если нормы не выполняются, схема раздвигается по горизонтали (наклон съездов
  и стрелочных улиц сохраняется, порядок элементов не меняется) — поэтому стыки
  больше не налезают друг на друга;
- чекбокс «Сетка (мм)» включает/выключает отображение сетки.

## Ручная правка на схеме

- ЛКМ по пути — добавить стык (красный, буква «р»);
- ЛКМ по стыку — удалить;
- ПКМ по стыку — сделать негабаритным / габаритным.

Участки и отчёт пересчитываются сразу. «Расставить стыки заново» сбрасывает правки.

## Зум

- колесо мыши — приблизить/отдалить к точке под курсором (от 50% до 6000%);
- Ctrl+ЛКМ или средняя кнопка мыши — перетаскивать схему;
- кнопки «−», «+», «Вписать» на панели, клавиши `+`, `-`, `0` (когда курсор над схемой);
- «Сохранить PNG» всегда сохраняет всю схему целиком, независимо от зума.

## Приближения

- **з** — стрелка, ответвление которой упирается в короткий тупик (< 3 междупутий),
  считается ведущей в предохранительный тупик и выделяется стыками со всех сторон.
- **Негабаритность** считается по геометрии схемы: междупутье на рисунке = 5,3 м,
  предельный столбик — где оси разошлись на 4,1 м, стык габаритный, если
  Lис ≥ Lпс + 3,5 м (рис. 2.11). Со стороны остряков стык ставится у рамного рельса.
  Стыки б/в/г/д/ж ставятся в ближайшее габаритное место, если оно помещается.
  Исключения по пособию: стык между спаренными стрелками съезда — габаритный,
  стыки стрелочной улицы — негабаритные.
- **Въезды**: главные пути продлеваются в сторону перегона, чтобы между стыком
  у входного светофора (а) и стыком перед первой стрелкой (в) был участок
  НП/НДП/ЧП/ЧДП; наличие этой зоны проверяется и выводится в отчёт.
- Обозначение стрелки рисуется со стороны остряков (тупой угол).
- Главными считаются пути, которые выходят к краям схемы с обеих сторон; нижний — I,
  верхний — II (как на рис. 2.1–2.7).
